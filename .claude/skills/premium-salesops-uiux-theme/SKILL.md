# Premium SalesOps UI/UX Theme Skill

Use this skill when designing, reviewing, or improving a frontend/UI-UX theme for a sales, customer service, WhatsApp inbox, CRM, AI review, or campaign dashboard product.

The goal is to create a UI that feels:

- premium
- modern
- professional
- enterprise
- trustworthy
- sales-oriented
- operationally clear
- decision-first
- not futuristic
- not generic AI SaaS slop

This skill is specifically for **frontend theme, UI direction, UX feel, layout, microcopy, and visual system**. It is not a backend, database, or infrastructure audit.

---

## 1. Core Positioning

The product should not feel like:

```text
AI magic tool
futuristic neon dashboard
generic SaaS template
random chatbot panel
decorative analytics screen
```

It should feel like:

```text
Premium SalesOps Command Center
WhatsApp Sales Control Desk
Enterprise Customer Operations Dashboard
Trust-first AI Review Console
Decision-first Sales Inbox
```

The UI must sell these values immediately:

```text
I can see important leads.
I know who needs reply first.
I can prevent risky AI messages.
I can control campaigns.
I can manage many WhatsApp accounts.
I can monitor sales and CS performance.
I can work faster without chaos.
```

If the screen does not communicate those values within 5 seconds, it is not premium. It is decoration.

## 3. Visual Direction

Use this design direction:

```text
Premium enterprise dashboard
Light neutral workspace
Dark navy sidebar
White cards
Teal/green action accent
Risk-aware status system
WhatsApp-familiar chat area
Right-side intelligence panel
Clean decision-first layout
Minimal decoration
Precise microcopy
```

The UI should feel expensive because it is calm, structured, specific, and useful.

Do not make it expensive by adding:

```text
heavy gradients
neon colors
glassmorphism overload
3D robot illustrations
AI purple everywhere
random glow effects
floating cards without hierarchy
excessive animation
```

Premium enterprise UI is not loud. It is controlled.

Usage rules:

- Use teal/green for primary actions and healthy WhatsApp-related status.
- Use blue for informational AI review or neutral intelligence.

- Use red for failed, blocked, dangerous, or high-risk states.
- Use navy for authority, structure, and enterprise feel.
- Do not use accent colors as decoration. Every color must communicate meaning.

## 5. Typography

Recommended fonts:

```text
Inter
Geist
Plus Jakarta Sans
```

Typography scale:

```text
Page title:       24–28px / 600–700
Section title:    16–18px / 600
Card title:       14–16px / 600
Body:             14px / 400–500
Small/meta:       12–13px / 400–500
Badge:            11–12px / 500–600
```

Rules:

- Avoid oversized marketing typography inside operational dashboards.
- Prioritize scanability over drama.
- Use weight and spacing before using color.
- Do not use more than 2 font families.
- Do not use random font sizes generated per screen.

## 6. Layout System

Recommended shell:

```text
Dark sidebar + white workspace + right intelligence panel
```

### Sidebar

Use a calm enterprise sidebar:

```text
Dashboard
Inbox
Accounts
Customers
Campaigns
Review Queue
Knowledge Base
Reports
Settings
```

Avoid too many “AI” labels. Too much AI language makes the product feel gimmicky.

Prefer business/operations labels:

```text
Review Queue
Risk Review
Lead Priority
Campaign Approval
Knowledge Gaps
Quality Control
```

Avoid:

```text
AI Magic
AI Brain
Super AI
Smart Booster
Autopilot Genius
```

### Dashboard

The dashboard should start with operational priority, not vanity metrics.

Good dashboard headline:

```text
Prioritaskan lead, review balasan AI, dan kendalikan campaign hari ini.
```

Good dashboard cards:

```text
12 balasan menunggu review
8 lead panas belum dibalas
3 akun WhatsApp perlu reconnect
5 campaign menunggu approval
4 knowledge gap ditemukan
2 percakapan perlu takeover
```

Bad dashboard cards:

```text
Total Users
Total Messages
Growth
Engagement
Performance
Revenue
```

Those are not always wrong, but they are weak if they do not help a decision.

### Conversation Page

Use a 3-panel layout:

```text
Left: Inbox list + lead priority
Center: WhatsApp-like conversation thread
Right: Sales intelligence + AI review
```

The right panel is the premium differentiator.

Right panel content:

```text
Lead status: Hot / Warm / Cold
Intent terakhir: Tanya harga / Minta lokasi / Siap survei / Komplain
AI mode: Draft / Supervised / Auto
Risk level: Low / Need Review / High
Suggested next action
Customer notes
Knowledge source
Follow-up reminder
```

Visual priority:

```text
1. Risk / status
2. Suggested next action
3. Customer context
4. Knowledge source
5. Notes/history
```

```text

```

But if the app only has generic components, it will feel like a template.

Component rules:

- Badge colors must map to status meaning.
- Cards must support decisions, not decoration.
- Tables must include clear actions and status.
- Empty states must suggest the next useful action.
- Error states must explain recovery.

## 8. Microcopy Style

Microcopy should be operational, specific, and action-oriented.

Avoid vague copy:

```text
Welcome back
Manage your conversations efficiently
Unlock seamless AI-powered engagement
Boost your productivity
Something went wrong
Submit
Get Started
Learn More
Campaign ready
AI generated a response
```

Use specific copy:

```text
8 lead panas belum dibalas dalam 15 menit terakhir.
Balasan ini perlu review sebelum dikirim.
AI membuat draft. Review admin diperlukan karena pesan menyebut harga.
Campaign siap dikirim ke 124 kontak. 9 kontak dikecualikan karena opt-out.
Gagal mengirim pesan. Coba lagi atau cek koneksi akun WhatsApp.
Hubungkan akun WhatsApp
Setujui campaign
Minta review admin
Jadwalkan follow-up
Tandai sebagai takeover
```

Microcopy rules:

- Every button must describe the action.
- Every error must explain what happened and how to recover.
- Every status must imply consequence.
- Every empty state must guide the next step.
- Avoid hype.
- Avoid vague AI language.
- Prefer operational clarity over marketing tone.

## 9. Landing/Login Page Direction

For landing or login screens, avoid generic AI SaaS claims.

Bad headline:

```text
AI-powered WhatsApp automation for your business
```

Better headline:

```text
Kelola banyak akun WhatsApp Sales & CS dari satu dashboard.
```

Strong subheadline:

```text
Prioritaskan lead, review balasan AI, jalankan campaign terkontrol, dan cegah pesan berisiko terkirim tanpa persetujuan admin.
```

CTA examples:

```text
Masuk ke Dashboard
Mulai Kelola Inbox
Hubungkan Akun WhatsApp
```

Trust-building elements:

```text
AI review before send
Controlled campaign approval
Multi-account WhatsApp monitoring
Human takeover support
Opt-out aware campaign flow
Knowledge gap detection
```

Do not sell “AI”. Sell:

```text
control
speed
trust
follow-up discipline
sales visibility
reduced operational chaos
```

A dashboard sells when it answers:

```text
What needs attention now?
What changed recently?

```

Use sections like:

```text
Needs Attention
Lead Priority
Review Queue
Account Health
Campaign Approval
Knowledge Gaps
Failed Sends
Follow-up Due
```

Avoid decorative analytics unless tied to action.

Good metrics:

```text
Hot leads waiting reply
Replies needing review
Accounts disconnected
Campaigns pending approval
Failed sends
Takeover conversations
Knowledge gaps
Follow-ups due today
```

Weak metrics:

```text
Total messages
Total users
Total conversations
Total contacts
Growth
Engagement
Performance
```

Those can exist lower on the page, but they should not dominate the first screen.

## 11. Chat UI That Sells

The chat page should communicate control and confidence.

Required states:

```text
AI mode visible
Draft vs sent clearly separated
Risk review visible
Human takeover visible
Customer stage visible
Last intent visible
Suggested next action visible
Failed send recoverable
Knowledge source visible
Internal notes separated from customer messages
```

Flag UI as slop when:

- AI draft looks like a sent message.
- Risk status is hidden.
- Admin cannot see why AI suggested a reply.
- Internal notes can be confused with customer replies.
- Failed sends disappear.
- Reply box is enabled when it should not be.
- Customer context is buried.

## 12. Visual Hierarchy Rules

Every screen must have:

```text
one primary focus
one primary action
clear status priority
secondary actions visually quieter
urgent/risky states clearly marked
consistent typography
consistent spacing
consistent badge system
```

Avoid:

```text
all cards same emphasis
too many colors
random shadows
random gradients
important alerts styled like normal cards
CTA hidden below decorative sections
typography size chaos
```

Premium is not the amount of UI. Premium is the clarity of priority.

---

## 13. State Completeness

Every important screen must include:

```text
default state
loading state
empty state
error state
success state
disabled state
validation error state
permission denied state
offline/disconnected state
pending approval state
failed action state
retry state
```

A UI with only the happy path is not finished.

Real products live in bad states. Demo products only live in ideal states.

---

## 14. Responsive Behavior

Mobile and smaller screens must preserve the workflow.

Check:

```text
Does the primary action remain visible?
Can the user read conversation threads comfortably?
Can tables/lists collapse into usable cards?
Do filters remain usable?
Do modals fit the viewport?
Are touch targets large enough?
Does the right intelligence panel collapse logically?
Is there horizontal overflow?
```

If desktop is simply squeezed into mobile, it is not responsive. It is unfinished.

---

## 15. Accessibility Baseline

Minimum requirements:

```text
buttons use button elements
links use anchor elements
inputs have labels
errors are connected to fields
keyboard navigation works
focus states are visible
color contrast is readable
icons have text or accessible labels
modals handle focus properly
status is not color-only
```

Premium UI that is inaccessible is fake premium.

---

## 16. Anti-Slop Review Checklist

Before approving a screen, ask:

```text
Can the user understand this in 5 seconds?
Is the next action obvious?
Does every card help a decision?
Is the copy specific or generic?
Are risk and pending states visible?
Does the UI handle empty/error/loading states?
Does it survive real customer data?
Does it work on mobile?
Can keyboard users operate it?
Is the component structure reusable?
Would this still work after 10 more features?
```

If the answer is no, revise.

---

## 17. Final Verdict Rules

### Approve

Use when:

```text
user goal is clear
visual hierarchy is strong
copy is specific
states are complete
mobile is usable
accessibility is acceptable
components are maintainable
the screen sells value through clarity
```

### Revise

Use when:

```text
the UI is usable but has weak copy, missing states, generic sections, or hierarchy issues
```

### Redesign

Use when:

```text
the layout is attractive but the flow is wrong
the dashboard does not support decisions
the page feels like a SaaS template
the product value is unclear
```

### Block

Use when:

```text
critical actions are unclear
users can mis-send or mis-approve
risk states are hidden
only happy path exists
accessibility is severely broken
frontend structure cannot scale
```

Do not ask:

```text

```

Ask:

```text
Does it sell trust?
Does it sell control?
Does it sell speed?
Does it sell safer AI usage?
Does it sell better follow-up?
Does it sell operational clarity?
```

If the UI is pretty but does not sell those outcomes, it is AI slop.
